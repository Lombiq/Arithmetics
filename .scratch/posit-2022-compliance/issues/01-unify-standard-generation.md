## Comments

- **Pre-implementation contract (Posit Standard (2022), original PDF, sections 3.2-3.3 and 4.1-4.3, pp. 6-8):** This ticket changes no numerical operation or rounding boundary. Existing Posit32, Posit32E2, and E0-E4 results and public signatures are preserved, not certified as standard-correct. The only shared algorithms are raw uint32 two's-complement and absolute-magnitude transforms; their contract is bit-for-bit `~bits + 1` and `(bits ^ (0 - signBit)) + signBit`, respectively, including zero and the NaR bit pattern. Tests use independently computed raw expectations for zero, NaR, signed extremes, and representative positive/negative encodings.
- **Known divergences and planned correction:** standard rounding/precision conversion differs in the assembly and constructor paths (ticket 03); comparison surface/ordering (02); integer construction/conversion (12-13); IEEE conversion (14); addition/subtraction intermediates (05); multiplication precision (06); division quotient/remainder handling (07); quire conversion (08); quire product/fused helpers (10); decimal parse/format adapters (15-16); and square root (30). Their current outputs are compatibility observations only, not a normative oracle. Each named operation ticket must converge its Posit32 and Posit32E2 standard entry points through one authoritative algorithm or generation source while keeping necessary public adapters explicit.
- **Hastlayer output review:** The transformer itself is unchanged. The shared helper calls add call-site handshakes and helper state machines to transformed VHDL; helper bodies implement the same raw bit formulas as the former inline expressions. The resulting snapshots therefore reflect the refactored call graph, not a transformer update or a numerical correction. The inlining sample has a large textual diff because the new calls are expanded at many sites and local/state identifiers shift; this is expected generated output, not unrelated source churn. Snapshot updates establish only the current transformation output and do not establish vendor synthesis, timing, simulation, or device behavior.
